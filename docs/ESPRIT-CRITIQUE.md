# Pourquoi Kora paraît fade — et comment on tient

À lire si tu n'es pas convaincu. L'idée soumise ne change pas. La lecture, si.

## Le malaise

Un CSV + quatre indicateurs + une phrase d'IA, ça ressemble à un dashboard. N'importe qui peut inventer 386 000 FCFA. Une banque n'a aucune raison d'y croire. Si on pitch « voici le revenu de Mariam », on mérite de perdre.

Ce n'est pas un détail. C'est **le** trou du projet.

## Ce que Kora n'est pas (même si le nom sonne fort)

- Pas une preuve que Mariam a vraiment vendu
- Pas une attestation, pas un notaire, pas la BCEAO
- Pas un score, pas une décision, pas une banque
- Pas Open Banking : on n'a pas les APIs

Si le produit *a l'air* plus vrai que ses sources, il est dangereux. Un menteur bien présenté est pire qu'un cahier.

## Ce qui est vraiment utile

Aujourd'hui, le partenaire reçoit un **tas** : photos WhatsApp, cahier, extraits partiels, mémoire. Il ne sait pas quoi a été choisi, pour combien de temps, ni ce qui est du cash déclaré vs un flux digital.

Kora ne résout pas « est-ce vrai ? ». Kora résout :

1. **Un dossier unique** que Mariam réutilise au lieu de tout recomposer
2. **Un partage borné** (champs + destinataire + durée + révocation)
3. **Un poids de la preuve visible** — y compris quand ça dessert Mariam

La praticité n'est pas « la banque croit Kora ». C'est « la banque lit un dossier structuré et voit *pourquoi elle ne doit pas encore croire* ».

## D'où vient l'innovation (sans mentir)

Rien n'est nouveau tout seul : agrégation de données, consentement, credentials, alternative data existent ailleurs.

La combinaison utile ici :

- l'entrepreneur **possède** le dossier (il n'est pas le sujet d'un bureau de crédit)
- le partenaire est un **invité à temps limité**
- le cash ouest-africain n'est pas caché : il est **marqué déclaratif**
- l'IA **explique**, elle n'autorise pas
- le passeport **ne peut pas masquer** le niveau de preuve

C'est de l'honnêteté outillée. Pas de la magie.

## Les failles qu'on assume à voix haute

| Faille | Ce qu'on en fait ce weekend |
|---|---|
| CSV inventable | On ne le nie pas. Grade « non attesté ». 0 % attesté dans la démo. |
| Le cash est invérifiable | On l'affiche en % déclaré. On ne le maquille pas en « digital ». |
| Pas d'API MTN / MoMo / banque | On ne les prétend pas. Phase 2 = attestation tierce. |
| Usurpation (ce n'est pas Mariam) | Hors MVP. On ne joue pas l'identité légale. |
| Le partenaire copie l'écran | Le consentement limite l'accès, pas un screenshot. On le dit si on nous le demande. |
| Formules naïves | Elles sont transparentes. Mieux qu'une boîte noire. |
| Œuf-poule banque / entrepreneurs | Le MVP convainc le *parcours*, pas le marché. |
| L'IA peut enjoliver | Texte déterministe d'abord. Jamais « crédit recommandé ». |

## Phrase à retenir pour le jury

> Kora ne demande pas de croire les chiffres. Kora empêche un dossier de paraître plus sûr que ses sources, et laisse l'entrepreneur décider ce qui sort — sauf le poids de la preuve, qui sort toujours.

Si cette phrase te paraît trop faible, le projet est trop faible. Si elle te paraît juste, tu as enfin le produit.
